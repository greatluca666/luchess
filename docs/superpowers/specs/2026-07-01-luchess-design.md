# luchess — 轻量朋友对弈网站 设计文档

日期: 2026-07-01

## 背景 / 目标

用户想和朋友下棋, 最初设想是裁剪lichess开源代码去掉注册/登录。经讨论确认: lichess是巨型monorepo(Scala后端+MongoDB+Redis+锦标赛/论坛/排名等系统), 裁剪成本远高于价值。改为**新写一个轻量对弈网站**, 借用lichess生态里的开源前端组件(chessground棋盘)保持体验一致, 但后端/工程量大幅简化。

无账号体系: 通过"创建对局→分享链接→对方直接入座"完成配对, 类似lichess的"friend game"无账号模式。

## 范围 (本期)

包含:
- 创建对局(选时限/选颜色), 生成可分享链接
- 两人通过链接实时对弈, WebSocket同步走子
- 计时器(常见时限制, 服务端权威计时, 超时判负)
- 认输 / 求和(需对方确认) / 悔棋(需对方确认)
- 观战模式(第三方打开链接自动只读旁观)
- 对局结束后落盘PGN+结果, 历史列表页可回放

不包含 (明确排除):
- 账号/登录/注册系统
- 锦标赛/排位/积分/论坛/好友系统等lichess其余功能
- 引擎分析(Stockfish)
- 服务端崩溃/重启后恢复进行中对局(初版跳过, 可作为后续增强)
- 反作弊/验证码/速率限制(朋友自用场景, 不需要)

## 技术方案

**选型: Node.js + TypeScript**, 单进程同时托管静态前端与WebSocket, 无需额外反代即可跑起来(后续如需HTTPS域名可加Nginx/Caddy, 属于部署细节非本设计范畴)。

- 后端: Express(静态文件+少量REST如历史列表) + `ws`(WebSocket房间同步) + `better-sqlite3`(落盘历史对局) + `chess.js`(权威规则校验: 合法走子/将军/绝杀/和棋判定)
- 前端: `chessground`(lichess官方开源棋盘UI组件) + `chess.js`(客户端即时校验, 减少往返等待感) + 原生TS, 不引入重框架(Vue/React均非必要, 页面结构简单)

**放弃方案:**
- 直接裁剪lichess代码库: Scala+Mongo+Redis全套环境, 工程量与本目标(两人对弈)完全不匹配
- Python+FastAPI: 前后端两种语言, 无额外收益
- 纯WebRTC P2P: 省不掉信令服务器, 且断线重连/观战/历史记录实现反而更复杂

## 数据流 / 房间生命周期

1. **创建对局**: 首页选时限(5+0/10+0/无限时等)+颜色(随机/白/黑), 提交后服务端生成`roomId`(不可猜测的随机短串)+房间内存状态(`waiting`), 返回`/game/{roomId}`并跳转。
2. **加入**: 打开链接建立WS连接。若房间`waiting`且未满员, 加入为对局第二方, 状态转`playing`, 服务端下发身份token(存localStorage, 用于断线重连), 广播开局状态(初始FEN+计时器启动)。若已满员, 自动转为观战(只读)。
3. **走子同步**: 客户端chess.js先做本地校验(即时反馈)→WS发送move→服务端chess.js做权威校验→更新房间FEN/回合/计时器→广播新状态给房间所有连接(含观战者)。
4. **计时器**: 服务端为权威时钟, 每次落子切换计时方并广播剩余时间; 超时由服务端判负并结束对局。
5. **认输/求和/悔棋**: 均走专属WS消息类型; 求和与悔棋需对方在客户端确认(接受/拒绝), 服务端转发请求与结果; 认输直接生效无需确认。
6. **结束**: 服务端把PGN+结果+双方用时写入SQLite, 房间状态转`finished`(只读留存), 内存中的房间在无人连接一段时间后清理(数据库记录永久保留)。
7. **历史回放**: `/games`列出SQLite中的对局, 点开用chessground+存的PGN在前端逐步回放。

## 错误处理 / 边界情况

- 非法走子: 客户端拦一道, 服务端权威校验兜底拒绝并不改变状态。
- 断线重连: 客户端带`roomId`+身份token自动重连, 服务端重发完整当前状态(FEN+计时器+历史), 界面据此恢复。
- 第三方尝试加入已满员对局: 服务端拒绝对局方身份, 强制转观战。
- 计时器超时: 服务端判负, 不依赖客户端时钟准确性。
- 服务端重启: 进行中对局状态在内存中, 重启即丢失(本期明确接受, 不做持久化恢复)。
- 无账号场景滥用: 不做速率限制/验证码; 仅靠`roomId`不可猜测性防止陌生人误入房间。

## 测试计划

- **单元测试(Vitest)**: chess.js规则封装、房间状态机各类转换(join/move/resign/draw-offer/undo-offer)、计时器扣减逻辑。
- **集成测试**: 起本地服务, 用ws客户端脚本模拟双方走完整局(含超时判负、悔棋/求和同意流程), 断言SQLite落盘记录正确。
- **手动验收**: 两个浏览器窗口连自建服务器, 真实走一整局, 验证计时器观感、断线重连、观战体验。
